- Pokémon screen (Kice's major-update spec §5, §6): Party and Summary are one glass screen (`ui/pokemonMenu.ts`, opened by the map's Party button and the reward screen's Party; the Summary button is gone). Left: the party list with a readiness dot, HP bar, LEAD/status tag. Right: seven tabs: Overview (sprite, types, HP, EXP progress, battle readiness, ability, nature, feeling, bond, evolution, moves and held-item summary), Stats (bars + comparison with the lead, or the second Pokémon when viewing the lead), Moves (list + power/accuracy/PP/priority and what the move does), Items (every held item with its real effects), Bond (bars, mood, personality, friendships, emotion), History (record, titles, memorable moments), Traits (evolution, Mega forms, mastery, shiny/hatched/lineage/vitamins/perk HP). Enter opens an action menu (Make lead, Move up/down, Review moves/items); up/down pick a Pokémon, left/right turn tabs; mouse works everywhere. Rearranging saves through `session.moveParty` (`Run.moveParty`, no save change). Item text is generated from the same hook data the battle engine reads (`core/itemEffects.ts`: passive vs triggered, numbers for the copies held, stacking, used-up, catches, a "N effects active" summary; a test fails when a new hook kind has no text). Pure helpers in `ui/pokemonInfo.ts`. Tests `tests/unit/pokemonScreen.test.ts`, `tests/e2e/pokemonMenu.spec.ts`. Limited: no taking an item off a Pokémon (held items are permanent run gear, the Bag thread owns item handling); no nicknames exist in the game; the Reward "give item" picker still uses the old party rows.
