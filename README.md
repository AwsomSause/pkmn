# Pokémon Roguelike

A browser-playable Pokémon-inspired roguelike built with TypeScript, Phaser 3 and Vite.

- Design: [GAME_DESIGN.md](GAME_DESIGN.md)
- Milestone plan: [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)
- What works right now: [CHECKLIST.md](CHECKLIST.md)

This repository is private. The art and audio come from the director's asset packs (see GAME_DESIGN.md §13 for licensing notes); do not publish builds publicly.

## Running the game

1. Install **Node.js 22** (LTS) from <https://nodejs.org>.
2. In a terminal, inside this folder:

   ```bash
   npm install
   npm run dev
   ```

3. Open the address it prints (usually <http://localhost:5173>).

Controls: **arrow keys** to move, **Enter / Space / Z** to confirm, **Esc / X** to go back. The mouse works too.

Handy extras:

- Add `?seed=anything` to the address to replay the exact same run (same starters, encounters and rewards).
- Press **F2** (or **`**) in dev mode to open the debug panel: run state, heal, swap the wild Pokémon, give items, add a Pokémon to the party, start a seeded run, and see missing assets. In a production build, add `?debug=1` to the address to enable it.

## Checking the code

```bash
npm run typecheck   # TypeScript checks
npm test            # unit tests for the game rules (Vitest)
npm run build       # production build into dist/
npm run test:e2e    # plays the game in a real browser (Playwright)
```

The first time you run the browser tests on a new computer, install the browser with `npx playwright install chromium`.

## Assets

Asset file names live in one place: `src/assets/catalog.ts`. The game only loads files listed in `public/assets/manifest.json`, which is generated by checking what actually exists. Anything missing is replaced by a labelled placeholder and listed in the debug panel.

To re-copy assets from the original zips (for example after adding new Pokémon to the data):

```bash
npm run assets:import -- /path/to/folder/with/the/zips
```

The folder should contain `images.zip`, `audio.zip` and `fonts.zip` as supplied. Only the files the game needs are copied.

## Project layout

```
src/core/      game rules (no Phaser): RNG, Pokémon, battle engine, catching, items, evolution, rewards, run state
src/data/      game content as JSON (species, moves, types, rewards, trainers, balance)
src/save/      versioned save system (browser storage now; cloud-ready interface)
src/game/      connects rules to saving (GameSession) and shared services
src/scenes/    Phaser screens: menu, trainer select, starters, battle, decisions (moves, catches), rewards, game over
src/ui/        reusable widgets, sprites, audio, text
src/debug/     developer panel
src/assets/    asset catalog (all file names)
tools/         asset import and manifest scripts
tests/unit/    rule tests        tests/e2e/   browser tests
```
